## 项目简介

Personal Quant Trading Agent 是一套围绕个人交易习惯设计的 A 股短线研究工具。它每天读取最近一个完整交易日的全市场收盘数据，先用确定性规则缩小股票范围，再对形态命中股补充历史行情、量价趋势、新闻公告、风险信息和可选的大模型研究。

它不是自动交易机器人，不连接券商下单，也不承诺收益。系统负责完成重复、耗时的市场研究工作，结果只作为使用者的观察和复盘材料。

> **规则负责筛选，AI 负责研究，人负责决策。**<br/>
> 大模型不会扫描 5,000 多只股票，也不能绕过形态规则和风险判断。

![研究工作台](docs/assets/dashboard.png)

### 目前可以做什么

- 浏览完整 A 股收盘快照，并查看每只股票是否通过基础条件。
- 自定义价格区间，以及是否纳入创业板、科创板。
- 用 OHLC 数学计算识别阳线完美十字和阳线锤子线。
- 对全部形态命中股加载历史 K 线，分析均线、趋势和成交量。
- 收集巨潮公告、东方财富新闻及可选 Tushare 新闻证据。
- 使用可选 DeepSeek 模型复核候选股，但最终评分仍由确定性规则完成。
- 展示每只候选股的理由、风险、新闻来源和综合评分。

## 工作流程

系统采用两阶段漏斗，避免无意义地对全市场逐股调用历史接口或大模型。

1. **读取全市场快照**：获取最近一个完整收盘日的全部 A 股行情。
2. **基础条件筛选**：按价格、板块、流动性、ST 和退市风险过滤。
3. **K 线形态筛选**：只保留阳线完美十字和阳线锤子线。
4. **逐股深度研究**：加载历史 K 线、成交量、趋势、新闻公告和风险数据。
5. **综合评分**：结合规则结果与可选模型意见，生成全部分析结果和重点关注列表。
6. **人工判断**：使用者只把证据用于自己的观察和复盘，系统不会自动执行任何交易。

```text
A 股全市场
    ↓
价格 / 板块 / 流动性规则
    ↓
阳线完美十字 / 阳线锤子
    ↓
历史行情 / 量价趋势 / 新闻公告 / 风险
    ↓
可选 DeepSeek 研究
    ↓
综合评分与人工决策
```

## 快速开始

### Windows 新手：双击打开

本分支提供一个不需要敲命令的本地入口。完成项目安装后，直接双击仓库根目录的 `run-web.cmd`，程序会在后台启动本地服务，并自动用 Google Chrome 打开“个人量化研究台”。

建议按页面上的顺序使用：

1. **运行演示**：使用内置数据熟悉报告，不联网、不消耗模型用量。
2. **获取收盘快照**：仅在北京时间工作日 15:01–15:15 抓取新浪公开收盘行情。
3. **生成真实研究**：只使用已经保存并验证为完整收盘日线的快照。
4. **Codex 解读最新报告**：调用前会再次确认，报告内容将发送给 ChatGPT/Codex 并消耗账户用量。

这个入口不连接券商、不自动交易、不创建定时任务，也不读取 `.env`。页面只绑定本机 `127.0.0.1:8765`；使用结束后可点击页面底部的“停止本地服务”。

### 小白版：持仓波段助手（核心仓 + 机动仓）

如果你的主要方法是基本面和长期持有，可以把这一部分理解成“在长期持仓旁边加一块观察仪表盘”。它只分析你已经录入的股票或 ETF，不负责从全市场挑选新标的，也不连接券商。

#### 怎么用

1. 双击仓库根目录的 `run-web.cmd`，Chrome 会打开本地“长期持仓波段助手”。
2. 点击“新增持仓”，填写代码、名称、资产类型、数量和成本。个人持仓只保存到本机；成本用于记录和页面展示，不会被拿来制造技术指标结论。
3. 在持仓卡片上点击“更新阶段判断”，查看“低位观察、低位反转信号、中性、高位观察、高位转弱信号”或“数据不足”。
4. 点击“历史模拟”，同时比较同一段历史中的“全程持有基准、静态核心仓 + 现金、动态核心仓 + 机动仓”三种口径。
5. 需要留档时，点击“打开个人报告”，进入本机 `data/private/reports/` 查看 Markdown 报告；报告中的数据截止日、依据和风险边界都应先看清楚。

#### 它到底在看什么

它不是用一个神奇形态预测精确底部或顶部，而是把几类比较容易解释的日线证据放在一起：

| 观察项 | 小白理解 |
| --- | --- |
| 近 120 日价格位置 | 当前价格在近一段时间的低处、中间还是高处 |
| 回撤 | 从这一段的相对高点回落了多少 |
| MA20 / MA60 | 20 日和 60 日平均价格，用来判断短中期环境偏上、偏下还是横盘 |
| RSI14 | 最近 14 个交易日涨跌力度，判断动能是否偏弱或偏强 |
| 布林带位置 | 观察价格是否靠近波动区间边缘，并参与低/高位观察区判断 |
| ATR | 记录最近波动有多大，作为复盘背景，不单独触发阶段判断 |
| 相对量能 | 记录成交量相对过去一段时间的变化，作为复盘背景，不单独触发阶段判断 |
| 反转确认 | 先进入低/高位观察区，再由后续日线出现同方向跟随；方向形态只作辅助，十字形态本身只表示犹豫，不能直接确认方向 |

主证据是 120 日价格位置和相对回撤，再由 RSI/布林带建立低位或高位观察区。只有在先出现观察状态后，后续日线的价格与 RSI 同向改善/走弱，或方向形态后出现对前一日高点/低点的跟随突破，并且趋势环境不相反时，才形成“低位反转信号”或“高位转弱信号”。规则刻意保持简单，不堆叠大量参数。

这些条件是“观察信号”，不是精确抄底或逃顶工具。趋势很强时，价格可能在高位继续上涨；下跌途中也可能多次出现看起来像底部的形态。因此页面不会把阶段标签写成执行指令。

#### 为什么不是高频交易

- 只使用已经收盘的日线，观察节奏是数周到数月，不处理分钟线和盘口变化。
- 历史模拟遵循“`t` 日收盘确认状态，下一根日线开盘模拟变化”，不会偷看当天收盘后的未来价格。前面的指标预热期只用于把计算所需历史长度补齐，不计入绩效。
- 至少需要 120 根完整日线；数据不足时只显示“数据不足”，不会编造收益率。
- 默认 20% 只是可编辑的历史模拟假设，允许在持仓卡片中调整；它不代表你的真实配置。模拟中的核心仓比例始终保持不变，机动部分只用于历史口径比较。

历史模拟会把同一评估区间同时放在三把尺子上：全程持有、静态核心仓 + 现金、动态核心仓 + 机动仓。新增的年化收益、年化波动率、Calmar 和市场暴露等，都是这段历史的统计描述，不是对未来的预测；预热期也不计入这些绩效指标。

程序还会固定检查三个连续历史阶段、阈值收紧/放宽约 20%，以及 2 倍/3 倍成本压力。它只报告结果是否对这些预设变化敏感，不搜索参数、不挑选表现最好的一组；“方向一致 4/4”也不等于策略已经被证明有效。

#### 股票、ETF 和成本边界

股票和 ETF 的交易制度、申赎方式、是否支持当日回转、最小申报单位及费率可能不同，不能只按名称猜测。工具要求明确选择“股票”或“ETF”，手续费、滑点和可能的单向税费是报告明示的固定示例假设，当前网页不可编辑，实际规则和券商费率需要自行核对。下一根日线如果没有成交量或成交额，历史模拟只延后暴露变化，不把它假定为已经成交。工具不会把成本价当作阶段判断依据，也不会据此自动改变你的真实持仓。

当前仍未模拟涨跌停、整手、最低佣金、分红/拆分的点时账务，以及实际组合相关性；前复权数据仅用于相对规则回放，不等同于逐笔可执行收益。

#### 数据和隐私边界

当前使用免费公开日线接口。公开接口可能延迟、限流、缺少交易日或临时不可用；复权方式、缺失数据和接口质量都会影响历史比较。数据源失败或不完整时，报告会明确提示，不用旧数据冒充新结果。

个人持仓文件、最近结果和报告固定放在仓库的 `data/private/` 下，并由 Git 忽略；个人持仓仍仅保留在 `data/private/` 和本机，不进 GitHub。它们只用于本机网页和本机运行，不应复制到 GitHub。代码仓库和测试只使用虚构数据，不能把真实代码、数量、成本或截图提交到公开仓库。建议你自行备份 `data/private/`，但备份也要放在自己信任的位置。

#### 持仓波段历史日线的多线路

持仓波段助手请求历史日线时，会按下面的固定顺序尝试公开来源：

`东方财富 →（存在非空 TUSHARE_TOKEN 时）Tushare Pro → 腾讯（AKShare）→ BaoStock`

这条链只服务于已经录入的单只股票或 ETF，不会把不同来源的 K 线按日期拼在一起。某个来源返回的整段数据只有在代码、资产类型、交易所、复权方式、日期顺序与范围、OHLCV 数值和单位都通过校验后才会被接受；失败或不完整就继续尝试下一条，并在报告中说明最终来源和是否发生切换。

- 股票：东方财富失败后，可在满足条件时依次尝试 Tushare Pro、腾讯和 BaoStock。
- ETF：无 `TUSHARE_TOKEN` 时只有东方财富；有非空 Token 时可尝试 Tushare Pro。腾讯和 BaoStock 当前明确不支持 ETF，因此不会被当作 ETF 的可用备份。
- `complete` 只表示收到的行通过了结构和字段校验，不证明源数据没有缺少交易日。免费公开接口没有 SLA，可能延迟、限流、改版或短时不可用；Tushare 还需要单独核实账号、积分和接口权限，不能仅凭安装成功视为可用。
- 发送给行情源的请求只包含公开代码、股票/ETF 类型、交易所映射、日期范围和复权方式，不包含本地持仓数量、成本、盈亏或备注。个人持仓仍只保存在本机 `data/private/`，绝不提交到 GitHub。

### 开发者方式

### 环境要求

- Python 3.11+
- Node.js 20+
- macOS、Linux 或 Windows WSL

### 1. 安装后端

```bash
git clone https://github.com/YishiQiu/personal-quant-trading-agent.git
cd personal-quant-trading-agent

python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev,api,data]'
cp .env.example .env
```

需要启用 Tushare Pro 历史日线时，再单独安装可选依赖：

```bash
pip install -e '.[tushare]'
```

启动 API：

```bash
uvicorn 'trading_agent.api:create_app' --factory --reload
```

后端启动后可以访问 [http://localhost:8000/docs](http://localhost:8000/docs) 查看接口文档。

### 2. 启动前端

另开一个终端：

```bash
cd frontend
npm ci
npm run dev
```

打开 [http://localhost:5173](http://localhost:5173) 进入研究工作台。

### 3. 可选：启用 DeepSeek

在本地 `.env` 中填写：

```dotenv
DEEPSEEK_API_KEY=your_key_here
```

不配置密钥也可以运行完整的规则筛选和确定性研究流程。密钥只由后端读取，不会发送到浏览器。

### 4. 可选：启用 Tushare Pro

先在本机安装 `tushare` 可选依赖，再把自己的 Token 只填写到本地 `.env`：

```dotenv
TUSHARE_TOKEN=
```

程序只在这个环境变量为非空时把 Tushare Pro 加入持仓历史日线的备选线路；不会把 Token 写入报告、日志、网页或请求展示。股票日线和 ETF 日线所需的 Tushare 接口、复权因子权限以及账号积分需要你单独真实验证；没有 Token 时，ETF 不会自动切换到腾讯或 BaoStock。

## 如何使用

1. 在首页设置最低价和最高价。
2. 选择是否纳入创业板和科创板。
3. 点击 **开始扫描**，系统会读取最近一个完整收盘快照。
4. 在 **形态命中** 中查看全部阳线完美十字和锤子线结果。
5. 点击 **分析全部股票**，补充历史行情、新闻公告和风险判断。
6. 在 **全部分析** 中逐只查看证据，在 **重点关注** 中查看综合评分较高的候选股。
7. 需要核对第一层筛选时，可进入 **全市场** 查看股票状态和具体排除原因。

### 使用最近完整收盘数据

免费公开源不保证盘中实时性，因此当前版本默认使用最近一个完整收盘日，而不是把未收盘的临时 K 线当作正式日线。

```bash
trading-agent capture-close --provider sina_free
trading-agent research --provider sina_free
```

系统只会在 09:15 前或 15:00 后把行情写入正式收盘快照。公开数据源失败时会保留上一次完整结果，不会用缺页数据生成推荐。

## 筛选逻辑

### 第一层：基础条件

默认筛选 3–100 元股票，并检查成交额、涨跌幅、ST 和退市风险。价格和板块范围可以直接在前端修改，其余参数位于 [`configs/market_scanner.yaml`](configs/market_scanner.yaml)。

### 第二层：K 线形态

全部使用 OHLC 数学计算，不使用图片识别。设总振幅 `R = H - L`，两种形态都要求 `C > O` 且 `R / O >= 3%`。

| 形态 | 默认定义 |
| --- | --- |
| 阳线完美十字 | `实体 / R ≤ 2%`；上下影各占 `R ≥ 45%`；影线差 `≤ 6%` |
| 阳线锤子 | 实体占 `R` 的 `3%–30%`；下影至少为实体 `2 倍` 且占 `R ≥ 60%`；上影不超过实体 `0.5 倍` |

T 字线和明显不对称的十字会被排除。所有阈值集中在 [`configs/workflow.yaml`](configs/workflow.yaml)，可以按自己的交易风格调整。

## 数据与模型

| 类别 | 当前来源 | 使用方式 |
| --- | --- | --- |
| 全市场行情 / 收盘快照 | 新浪、东方财富 | 基础扫描；使用最近一个完整收盘日 |
| 持仓波段历史日线 | 东方财富 → Tushare Pro（可选）→ 腾讯（AKShare）→ BaoStock | 已录入股票或 ETF 的阶段判断与历史模拟；按资产类型限制可用来源 |
| 公司公告 | 巨潮资讯 CNINFO | 只查询已经入围的候选股 |
| 个股新闻 | 东方财富 / AKShare | 只查询已经入围的候选股 |
| 补充新闻 | Tushare，可选 | 取决于账号接口权限 |
| 研究模型 | DeepSeek，可选 | 只读取规则筛选后的候选股 |

> [!WARNING]
> 免费网页接口可能限流、改版、延迟或缺失。项目适合个人低频研究与工程实践；生产或商业用途应替换为有授权和服务保障的数据源。

持仓波段历史日线不会跨来源拼接。报告会显示最终实际来源，以及是否从前一条线路切换；所有线路失败时只显示数据不可用和已尝试的公开来源，不会用旧结果冒充本次结果。

## 改成自己的项目

可以点击 GitHub 首页的 **Use this template**，创建一份不包含原提交历史的新仓库：

**[使用当前模板创建项目 →](https://github.com/YishiQiu/personal-quant-trading-agent/generate)**

创建后建议按以下顺序修改：

1. 修改 [`frontend/src/branding.ts`](frontend/src/branding.ts) 和 README，换成自己的名称与介绍。
2. 调整 [`configs/`](configs/) 中的股票范围和形态阈值。
3. 按 [复刻与改版指南](docs/customization.md) 接入自己的行情、新闻或模型服务。
4. 使用固定行情快照运行测试，确认改版没有改变预期的数据边界。
