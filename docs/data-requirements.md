# 数据接入清单

下面列出当前工程的行情接入边界。全市场扫描 Provider 位于 `src/trading_agent/providers/`，持仓波段历史日线 Provider 位于 `src/trading_agent/swing/`；两条工作流的来源和失败策略不要混用。

| 能力 | 何时使用 | 最低接口要求 | MVP 选择 |
|---|---|---|---|
| 全市场收盘快照 | 每交易日 15:01 后缓存 | 一次返回 A 股代码、名称、完整开高低收、成交量、成交额 | `sina_free` 为当前默认；`eastmoney_free` 保留给全市场公开行情链路；AKShare 为兼容适配器 |
| 候选股历史日 K（全市场扫描） | 形态筛选后读取 | 至少返回可用的 OHLCV 和交易日 | 全市场扫描沿用对应快照 Provider 的候选研究接口；它与持仓波段历史线路分开 |
| 持仓波段历史日 K | 收盘后；持仓阶段判断和历史模拟时读取 | 返回策略所需的完整 OHLCV、复权方式、交易日；当前最低判断长度由策略配置控制 | 固定顺序：东方财富 →（非空 `TUSHARE_TOKEN` 时）Tushare Pro → 腾讯（AKShare）→ BaoStock |
| 同时段量能 | 候选研究 | 历史 1 分钟或 5 分钟累计量/额 | Tushare Pro 分钟权限或已授权行情源 |
| 新闻与公告 | 盘后、盘前、14:30 | 标题、正文或摘要、发布时间、URL、公司/主题映射 | 已实现：CNINFO 候选公司公告（官方 PDF 链接）+ AKShare/东方财富候选股新闻；可选 Tushare `major_news` 精确代码/全称归因 |
| 板块/概念 | 候选研究 | 行业、概念成分、板块涨幅、板块资金 | AKShare 原型；授权源更稳定 |
| 资金流 | 候选研究 | 个股主力净流、北向、融资余额；时间戳 | Tushare Pro / 授权数据源 |
| 基本面 | 每日或每周缓存 | PE、PB、ROE、营收/利润增速、披露期 | Tushare Pro / 财报数据源 |
| LLM 研究 | 仅研究池 | 受 JSON Schema 约束的模型 API；不得使用自由文本作为决策输入 | OpenAI / 其他兼容模型 |

## 持仓波段历史日线的多线路

持仓波段助手每次只请求一只已经录入的股票或 ETF，默认按以下顺序尝试：

`东方财富 →（存在非空 TUSHARE_TOKEN 时）Tushare Pro → 腾讯（AKShare）→ BaoStock`

其中：

- 股票可以在东方财富失败后，依次尝试 Tushare Pro、腾讯和 BaoStock。
- ETF 无 Token 时只有东方财富；有非空 Token 时可尝试 Tushare Pro。腾讯的 `stock_zh_a_hist_tx` 和 BaoStock 当前实现只支持股票，不会被伪装成 ETF 备份。
- Tushare 是单独的可选依赖和可选线路；只有环境变量 `TUSHARE_TOKEN` 非空时才加入。Token 不写入代码、报告、日志或网页，也不在请求结果中回显。Tushare 的股票/ETF 日线、复权因子和新闻接口还要结合账号积分与权限单独真实验收。

每次只接受一个来源返回的整段历史，不跨来源按日期拼接。统一边界校验包括代码、资产类型、交易所、复权方式、日期范围/顺序/唯一性、OHLCV 数值以及成交量和成交额单位；不通过就继续下一条线路。成功结果的报告显示最终来源，若前序失败则显示“已自动切换”；全部失败时只列出尝试过的公开来源和不可用状态，不暴露底层异常、URL 或 Token。

请求发送给行情源的内容仅限公开代码、资产类型所需的交易所映射、日期范围和复权方式；本地持仓数量、成本、盈亏、备注等字段不进入请求，也不进入公开仓库。

`complete` 只表示收到的行通过了结构和字段校验，不证明源数据没有交易日缺口。免费公开端点没有可依赖的 SLA，也不等同于可商用的数据授权；它们可能延迟、限流、改版或临时不可用。系统把它定位为个人、低频、人工复核的研究输入，不能把一次成功探针理解成长期可用保证。

## 全市场快照与候选股扫描

`eastmoney_free` 是全市场公开行情链路之一，不依赖 AKShare 或其他第三方 Python 包。为降低连续全市场分页导致的连接重置，它固定为单线程、每页 0.4 秒间隔、最多 3 次指数退避重试；约 56 页的完整快照通常需要约 25 秒以上。它不做并发抓取，也不会在缺页后悄悄返回已有数据。

`sina_free` 是当前默认的前收盘筛选 Provider。它在收盘后缓存完整快照；下个交易日的研究流程自动读取最近缓存，并只在形态筛选后拉取候选股历史 K。该来源的历史 K 没有历史成交额，因此历史成交额字段明确记为 0，涉及历史成交额的分析必须等待更完整的数据源。

全市场快照或候选研究 Provider 无法取得完整数据时，命令行以非零状态退出并输出 JSON 错误；API 则返回 `503`。这表示本次没有产生研究结论，不应把上一次结果误当作当天的前收盘筛选结果。

## 现在需要你提供的内容

框架和 `demo` 工作流已可运行。全市场扫描的 `eastmoney_free` 与 `sina_free` 提供免费快照与候选研究；持仓波段历史日线的腾讯和 BaoStock 需要安装 `data` 可选依赖，Tushare 需要再安装 `tushare` 可选依赖并配置环境变量。接入完整生产链路前，需要确认：

1. 一个可用于 AKShare（腾讯历史日线）原型网络访问的环境，或 Tushare Pro Token 与已购买的权限范围；BaoStock 也需要实际网络连通性。
2. 若需要媒体新闻，提供具备 `major_news` 权限的 Tushare Pro Token；未提供时仍会运行已接入的 CNINFO 公告，但不会虚构媒体催化。历史日线权限和新闻权限分别核对。
3. 是否需要同一时刻历史量能。若需要，必须有分钟数据权限或授权行情源。
4. 选择一个 LLM API 并提供其安全配置方式；密钥和 `TUSHARE_TOKEN` 只放在环境变量或密钥管理服务中，绝不写进 YAML、报告或仓库。

Level-2、逐笔成交、委托簿、竞价撤单均不属于当前 14:30 单次快照 MVP；未来若启用，需单独采购并核实授权。

## 明确排除的数据来源

- Kimi 内置或插件形式提供的同花顺数据不得被本项目自动读取、导出、缓存、转发或用于任何评分、回测和推荐。其可见性不等于项目获得了外部 API 或再利用授权。
- 同花顺及其他第三方页面数据只有在取得明确的、适用于本项目自动化用途的授权后，才能新增对应 Provider。
- AKShare 是数据接入库，不代表其每个上游页面都获得再利用授权；当前项目已通过 AKShare 接入腾讯股票历史日线，同时仍未接入任何 AKShare 的 `*_ths` 或同花顺上游接口，这些接口保持禁用。
